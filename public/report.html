ABSTRACT

College students and hostel residents face acute hurdles in managing limited monthly allowances. The coexistence of liquid physical cash and digital UPI (Unified Payments Interface), combined with frequent shared group expenditures—such as hostel room supplies, shared grocery runs, flat rents, and mess bills—frequently leads to premature budget exhaustion, untracked peer debts, and social awkwardness among roommates. Existing commercial expense trackers either overcomplicate workflows with corporate taxation features, fail to segregate UPI from Cash balances, or treat group debt settlements as mere self-declared checkboxes without two-party mutual verification.

PocketBuddy — Student Smart Money Manager is a modern, responsive full-stack web application designed specifically to address the financial lifestyle of college students. Built with React 19, TypeScript, Tailwind CSS, Express.js, and Firebase Firestore, PocketBuddy provides a unified, robust platform featuring:

  1. Dual-Wallet Pocket Money Tracking: Real-time independent balance tracking for physical Cash and digital UPI with category-based personal expenditure logging.
  2. Multi-User Room Expense Manager: A collaborative group budgeting system where roommates join via secure invite codes, split shared bills using an exact integer-paise algorithm with zero rounding loss, and calculate a live "Who Owes Whom" debt graph.
  3. Receiver-Approved Settlement Protocol: A two-step financial reconciliation state machine ensuring that debt settlements remain in a PENDING status until the receiving creditor explicitly verifies and approves the payment.
  4. Confidential Student Vault: A password-protected client-side notes manager for storing private financial credentials, lease agreements, and PINs.
  5. AI-Assisted Receipt Parsing: Prototype integration with Google Gemini 2.5 Flash and Tesseract OCR for automated receipt transcription.

Rigorous experimental validation across multi-device concurrent sessions verified 100% mathematical accuracy with zero drift across non-terminating decimal splits, robust role-based authorization, and strict user data isolation.

Keywords: Personal Finance, Expense Splitting, Two-Party Settlement, Integer-Paise Arithmetic, React 19, Express.js, Firebase Firestore, Full-Stack Web Engineering.

CHAPTER 1
INTRODUCTION

1.1 Project Overview

Personal financial management is a critical yet universally challenging aspect of student life. College undergraduates, especially hostelers and outstation students residing in shared apartments or paying guest (PG) accommodations, operate under strict monthly financial constraints. Allowances received from parents or earned through part-time endeavors are finite and must cover academic books, cafeteria meals, transport, leisure, and shared household necessities.

In recent years, the Indian financial ecosystem has undergone a monumental shift toward cashless transactions powered by the Unified Payments Interface (UPI). However, the physical reality of student life demands a hybrid financial workflow: small canteen purchases, local transport, and emergency medical supplies are often transacted in liquid cash, whereas online orders, tuition, and major shared bills are settled through UPI. This dual-wallet reality creates severe tracking blind spots. Students frequently observe an alarming dissonance between their digital account balance and their physical cash reserves.

PocketBuddy — Student Smart Money Manager is an engineered full-stack software solution built specifically to eliminate this chaos. It combines personal dual-wallet budgeting (Cash vs. UPI) with a multi-user collaborative room management hub, providing students with full transparency over their personal savings and roommate debt obligations.

1.2 Problem Statement

The primary problems targeted by this project can be formulated into four distinct operational bottlenecks:

  1. Cash vs. Digital Fragmentation: Traditional personal finance mobile applications link exclusively to bank SMS feeds, ignoring liquid physical cash entirely. When students withdraw cash from an ATM, commercial trackers classify the entire withdrawal as an instantaneous expense, destroying tracking granularity for subsequent cash outlays.
  2. Shared Living Expense Friction: In shared rooms, flatmates alternate purchases—one buys milk, another pays the electricity bill, and a third buys cooking gas. Manual record-keeping on paper ledgers or WhatsApp groups creates disputes, forgotten dues, and awkward social interactions.
  3. Unilateral Settlement Exploitation: In widely used group expense apps, a debtor can unilaterally tap "Mark as Settled" without the creditor ever receiving the actual money. PocketBuddy resolves this through a two-step receiver-approval state machine.
  4. Fractional Penny Rounding Drift: Dividing odd sums across three or seven flatmates (e.g., ₹313 ÷ 3 = ₹104.3333...) leads to fractional rounding discrepancies if handled with naive 64-bit floating-point numbers. PocketBuddy implements a provably zero-sum integer-paise allocation algorithm.

1.3 Project Objectives

The principal objectives of this B.Tech CSE mini-project are:

  • To build a responsive, client-side web application using React 19, TypeScript, and Tailwind CSS.
  • To architect a secure Node.js Express REST API backed by Firebase Firestore for real-time document synchronization.
  • To enforce strict multi-tenant user data isolation so that each student's personal finances remain private.
  • To implement a mathematically rigorous integer-paise group expense splitting engine that guarantees zero penny drift.
  • To engineer a creditor-verified settlement protocol requiring receiver consent before debt cancellation.
  • To provide a confidential, PIN-encrypted vault for storing sensitive credentials and hostel room agreements.

4.2 Mathematical Zero-Sum Split Algorithm

A key innovation in PocketBuddy is its integer-paise split logic. Floating-point division (e.g. ₹313 / 3 = 104.333333) causes penny mismatches in database records. PocketBuddy maps all Rupee amounts to integer paise: 

function splitEquallyIntegerPaise(totalRupees: number, memberIds: string[], payerId: string) {
  const totalPaise = Math.round(totalRupees * 100);
  const n = memberIds.length;
  const baseShare = Math.floor(totalPaise / n);
  const remainder = totalPaise % n;

  // Remainder paise are systematically allocated to the payer to guarantee sum == total
  return memberIds.map(id => ({
    userId: id,
    shareRupees: (id === payerId ? baseShare + remainder : baseShare) / 100
  }));
}
